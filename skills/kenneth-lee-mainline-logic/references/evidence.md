# 方法依据

- [软件构架设计/主线逻辑.rst](https://github.com/Kenneth-Lee/MySummary/blob/master/软件构架设计/主线逻辑.rst)：讨论复杂对象时先抓使其成为该对象的主干规律，不让例外吞没讨论。
- [软件构架设计/逻辑链，道，学和架构工作的本质.rst](https://github.com/Kenneth-Lee/MySummary/blob/master/软件构架设计/逻辑链，道，学和架构工作的本质.rst)：把目标、因果和现实约束组织为可持续修正的链条。
- [软件构架设计/逻辑闭包.rst](https://github.com/Kenneth-Lee/MySummary/blob/master/软件构架设计/逻辑闭包.rst) 与 [逻辑闭包V2.rst](https://github.com/Kenneth-Lee/MySummary/blob/master/软件构架设计/逻辑闭包V2.rst)：把同一主语、同一问题域的条件封闭起来，才能判断完整性和一致性。
- [软件构架设计/主语问题.rst](https://github.com/Kenneth-Lee/MySummary/blob/master/软件构架设计/主语问题.rst)：先确定主体及其可见刺激，避免“上帝视角”掩盖实现者的缺口。
- [软件构架设计/确定逻辑的根.rst](https://github.com/Kenneth-Lee/MySummary/blob/master/软件构架设计/确定逻辑的根.rst)：稳定性来自目标相关的变更成本和依赖关系，而非现有组织、版本或模块名字。
- [软件构架设计/基于逻辑链建立约束.rst](https://github.com/Kenneth-Lee/MySummary/blob/master/软件构架设计/基于逻辑链建立约束.rst)：高层只用已知信息给下一层制造必要约束，明确“不知”以保留自由度。
- [软件构架设计/从香农熵谈设计文档写作.rst](https://github.com/Kenneth-Lee/MySummary/blob/master/软件构架设计/从香农熵谈设计文档写作.rst)：只有能收缩决策可能性的内容才有信息价值。

边界：主线是当前目标下的抽象，不是声称例外不存在；闭包也不意味着现实可以被完全穷举。
