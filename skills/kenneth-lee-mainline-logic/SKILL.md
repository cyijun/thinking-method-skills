# 主线逻辑推演

把散乱事实组织成一条能从现实条件通向目标、并能暴露断点的逻辑。重点不是搜集更多“正确的话”，而是确定哪些信息改变当前判断。

## 推演

1. 写出原始目标。把用户真正要得到的结果与当前提议的方法分开，避免用设计结果反推需求。
2. 固定主语和观察范围。每条逻辑链只在一个主体的可见信息、可执行行为和责任范围内展开。
3. 找逻辑根：选择更接近原始目标、更难改变、被更多实体依赖或变更成本更高的事实作为起点。组织、模块名和当前实现通常不是稳定根。
4. 建立最短主链：条件 → 行为或机制 → 中间结果 → 目标。每一步写出依据、置信度和未知。
5. 把相对独立的问题拆成逻辑闭包。闭包应有明确边界、输入或刺激、内部规则、输出和异常；不同闭包不要在一句话里切换主语。
6. 从主链导出最小约束。只加入达成目标所必需的限制，把其余空间留给下一层设计。
7. 检查替代路径、失败条件和反例。若一个结论无法排除合理替代解释，就把它保留为假设。

## 有效性检查

- 删掉这条信息，结论或选择会改变吗？不会改变的信息不应占据主线。
- 每个因果连接有事实、机制或明确假设支撑吗？
- 结论是必要条件、充分条件，还是只是相关现象？
- 逻辑是否从一个主体悄悄跳到另一个主体？
- 闭包是否覆盖了所有关键输入、状态和异常？
- 约束来自目标，还是来自现有代码、组织习惯或个人偏好？

## 输出

优先输出：

- 目标、主语和范围；
- 逻辑根；
- 主线链条；
- 并列闭包及接口；
- 最小约束；
- 关键未知、替代解释和失效条件；
- 当前可做的决定。

不要用篇幅、术语或“没有明显错误”冒充完整论证。需要追溯来源或理解逻辑链与概念空间的关系时，读取 [references/evidence.md](references/evidence.md)。
