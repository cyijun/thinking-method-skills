# 模型驱动调研

调研的目的不是把资料看完，而是建立一个能解释现象、引导下一步验证的临时模型。模型可以错，但必须足够明确，使错误能被证据暴露。

## 调研

1. 定义要支持的判断、时间或版本基线、允许投入的深度，以及错误结论的代价。
2. 用当前信息建立第一版模型：核心对象、关系、主线流程、控制要素和最大未知。不要等“掌握全部事实”才开始组织。
3. 建立证据分层：
   - 一手定义：规范、代码、补丁、数据结构、提交记录；
   - 直接观测：日志、运行结果、可重复实验；
   - 二手说明：维护者说明、文档、可信总结；
   - 推断：由前述证据得到但尚未独立验证的结论；
   - 未知：当前模型没有覆盖或无法判定的部分。
4. 优先追踪主线到一手来源。沿调用链、状态变化、提交或协议关系验证关键连接，避免停在术语介绍。
5. 为互相竞争的解释设计区分性探针。一次调查尽量回答“哪种模型更能解释事实”，而不是再增加一批相关资料。
6. 每获得关键证据就更新模型、置信度和调查范围。保留被推翻的假设及推翻原因，防止换个名字重新引入。
7. 到达决策所需的证据强度就停止；若代价高或证据不足，给出条件性结论和下一验证点。

## 输出

- 问题、范围、版本和决策用途；
- 当前概念模型与主线；
- 逐条证据链及证据级别；
- 已验证事实、推断和未知；
- 被排除的替代解释；
- 结论、置信度、反证条件；
- 下一步最有信息增益的检查。

不要把模型写成不可质疑的真理，不要用二手总结支持精确实现结论，也不要因为一次实验成功就把个例扩展为全集。快速调研尤其要显式说明其时效和臆测边界。
