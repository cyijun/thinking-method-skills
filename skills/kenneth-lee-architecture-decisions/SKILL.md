# 架构决策设计

架构工作是为未知和未来划出可用边界，使下一层设计既能完成目标，又保留必要自由度。架构文档必须形成决策面，而不是代码摘要、功能清单或格式完整的空话。

## 依赖链

按以下依赖关系推进并反向校验：

目标 → 设计逻辑与新概念 → 核心数据结构 → 用户接口 → 实现与验证

任何一层不能支撑上一层，都应回退修正，不要用后续细节掩盖前面的错误。

## 设计

1. 复述目标、非目标、用户及当前系统状态。去掉已夹带的方案和宣传性语言。
2. 找出实现目标的主要矛盾、关键取舍和失败风险。没有取舍的问题简述即可。
3. 枚举高层可选路径，说明得到什么、放弃什么。穷举的是抽象层的可能性，不是所有代码细节。
4. 为每个关键选择建立决策面：明确主语、范围、候选项、约束、选择理由和失效条件。按需要使用概念、开发、处理、状态机或用例等视图。
5. 在解决关键矛盾时创造必要的新概念。说明新概念由哪些旧概念组合而来、封装了什么复杂性；后续数据结构和接口应直接使用它。
6. 定义核心数据结构。逐项检查设计逻辑承诺的能力是否有数据承载，生命周期、所有权、状态和关系是否明确。
7. 定义最终用户接口。每个接口追溯到目标或决策；每个目标都有可实现路径。明确错误、并发和版本语义中真正影响边界的部分。
8. 用最小实现、状态机推演、测试或原型验证高风险逻辑，再根据反馈重构概念和边界。

## 输出

- 目标、非目标和设计基线；
- 主要矛盾与候选方案；
- 概念空间；
- 若干完整决策面或视图；
- 不变量、自由度和层次边界；
- 核心数据结构；
- 用户接口；
- 目标到接口的追溯；
- 风险、未知、验证与演进触发器。

避免把现有代码画成图、把细节特征当设计、提前填满未知、只证明个例能跑，或假设第一次建模就会正确。使用 AI 时，人负责目标、概念选择和主要矛盾，AI可加速展开、实现和校验，但反馈必须回到依赖链。
